# P2 · 积木帖子 —— 开工说明

## 一、你要做的事，一句话

把「帖子」从**一坨 Markdown 文本**变成**一串有序的积木块**。每块有类型（文字、Wiki、外链表、投票、小程序…），能排序、能插、能删、能导入导出。配套两个编辑模式：「编辑」（现有的 LaTeX 实时预览 + AI 抽屉）和「高级编辑」（像 GitHub 那样可编程）。还要做**内置模板**，Wiki 模板优先。

详细需求（逐条带编号）：`docs/01-需求规格说明书.md` 里 P2 那一段。

> ## ⚠️ 你是关键路径

**这一路是整个 v2 的地基。** 理由：

```
P2 的 documents / document_blocks
   ├─→ P3（AI）要读这两张表才能「对着积木改稿」
   └─→ P4（团队）要判断文档的可见范围才能实现「仅团队可见」
```

**时间紧就给 P2 加人，不要给 P4 加人。** 需求和分工文档里都重复写了这句话。

**你的工作量也是最大的一路。**

## 三、你的地盘（只动这些）

### 后端

```
src/modules/doc/            ← 你的整个目录，随便建文件
   index.js                            ← 模块声明 + install(ctx) 里建表登记路由
```

**接口前缀：`/api/docs/*`** —— 只在这个前缀下加路由。

### 表的归属

| 表 | 谁建 | 说明 |
|---|---|---|
| `documents` | **你** | 文档本体：作者、标题、可见范围、模板类型、时间 |
| `document_blocks` | **你** | 有序积木块：文档 id、**`position` REAL**、类型、内容 JSON |
| `posts` `users` `reactions` `coins` | core | **只读**。tag / 点赞 / 投币仍然走 core 现有的表和接口 |

建表**不要自己写 `CREATE TABLE` 执行**，要登记：

```js
ctx.schema.add('documents', `
  CREATE TABLE IF NOT EXISTS documents (
    ...
  );
`, 'doc');
```

表名必须出现在 `index.js` 的 `owns` 数组里，否则 `check-skeleton.mjs` 会报错。

### 前端

```
public/views/doc.js      ← 新建，你的页面
public/css/41-doc.css         ← 新建，你的样式（两位数字前缀决定加载顺序）
scripts/doc-smoke.mjs           ← 新建，你的端到端测试
```

注册页面要在 `public/app.js` 加一行 import、在 `public/core/router.js` 加一段路由。样式要在 `public/style.css` 顶部加一行 `@import`。

### 合并时你只动一行

`src/modules/index.js` 的 `MODULES` 数组里加一项：

```js

```

## 八、你这一路最容易踩的坑

**坑 1：别把文档塞进 `posts` 表。** 你要新建 `documents`。但**引用**关系要想清楚——如果一篇可编程帖子在站点上也要出现在帖子列表里，就得跟 core 的 `posts` 有一一对应关系。这是你开工第一件要想明白的事。

**坑 2：`position` 一定要用 REAL。** 用 INTEGER 的话，插一块就要把后面所有块 +1，块一多就会写成 N 条 UPDATE，还容易并发写坏。REAL 让你直接插 `3.5`。

**坑 3：小程序/小游戏的「沙箱」不是可选项。** 用户写的代码要在服务端渲染之前就控制住，不能让它碰到 `ctx.db`、不能让它 `import` 任何东西。这是需求里的安全底线，写在 02 文档的「为什么非要沙箱」里。

**坑 4：块内容存 JSON 还是分列存？** 建议存 JSON 文本（`content_json`），因为块类型会不断增加，每加一种就 `ALTER TABLE` 一次不现实。但**要把类型单独抽成一列**，不然没法按类型查询。

**坑 5：你没做出来，P3 和 P4 都要等。** 所以**先把两张表的 schema 定下来并写进代码、先跑通「存一块、读一块」**，哪怕编辑界面还是个丑的——先让别人的依赖能落地。

## 九、常见问题

**Q：我可以改 `src/modules/core/routes-a.js` 里的一个小地方吗？**
A：不行。那是现有论坛的接口，改了 `check-golden.mjs` 会红，而且红在哪很难查。真有需求，先提出来。

**Q：我要的数据在别人的表里怎么办？**
A：用 `ctx.db` 直接读（表结构是公开的），或者看 `ctx.store` 里有没有现成的方法。**不要 import 别人的文件。**

**Q：我新增了文件，为什么测试没报错？**
A：因为哨兵没调。去 `scripts/check-encoding.mjs` 的 `REQUIRED_FILES` 里加上你的新文件，把 `MIN_CHECKED` 加 1；前端新增页面就同步调 `check-ui-contract.mjs` 的 `MIN_UI_CHECKS`。**不做这一步，测试会静默变绿、漏洞静默变大。**

**Q：`check-golden.mjs` 红了怎么办？**
A：说明你改到了现有行为。先 `git stash` 看你到底改了哪些文件，**大概率是你碰了 `src/core/` 或 `src/modules/core/` 里的东西**。绝对不要用 `--write` 重新采样来"修好"它——那是把行为改变合法化。

**Q：`node --test` 报 EPERM？**
A：预期内。这个项目**不用** `node --test`，照抄 `scripts/smoke.mjs` 的写法。

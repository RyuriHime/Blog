## 三、你的地盘（只动这些）

### 后端

```
src/modules/team/            ← 你的整个目录，随便建文件
   index.js                            ← 模块声明 + install(ctx) 里建表登记路由
```

**接口前缀：`/api/teams/*`** —— 只在这个前缀下加路由。

### 表的归属

| 表 | 谁建 | 说明 |
|---|---|---|
| `teams` | **你** | 团队本体：slug、名字、简介、创建者 |
| `team_members` | **你** | 成员关系：团队 id、用户 id、角色、加入时间（主键 `(team_id, user_id)`） |
| `documents` `document_blocks` | P2 | **只读**，等 P2 先把表建出来 |
| `posts` `users` `notifications` | core | 只读 |

建表**不要自己写 `CREATE TABLE` 执行**，要登记：

```js
ctx.schema.add('teams', `
  CREATE TABLE IF NOT EXISTS teams (
    ...
  );
`, 'team');
```

表名必须出现在 `index.js` 的 `owns` 数组里，否则 `check-skeleton.mjs` 会报错。

### 前端

```
public/views/team.js      ← 新建，你的页面
public/css/86-team.css         ← 新建，你的样式（两位数字前缀决定加载顺序）
scripts/team-smoke.mjs           ← 新建，你的端到端测试
```

注册页面要在 `public/app.js` 加一行 import、在 `public/core/router.js` 加一段路由。样式要在 `public/style.css` 顶部加一行 `@import`。

### 合并时你只动一行

`src/modules/index.js` 的 `MODULES` 数组里加一项：

```js
export const MODULES = [core, team];
```

## 八、你这一路最容易踩的坑

**坑 1：不要一上来就做实时协同。** 现有网站是「谁最后保存谁算数」——没有版本号、没有冲突提示、没有任何实时通道。需求文档和分工文档都明确写了建议：**先做「版本号 + 冲突提示」（改动小、解决真痛点），实时协同放第二期。** 直接上 WebSocket 会吞掉你全部时间，而且这个项目是零依赖的（不许加 `socket.io`），你得手写。

**坑 2：可见性判定必须在服务端，而且返回 404 不是 403。** 现有 `assertPostVisible` 对非 staff 非作者返回 `404 post_not_found`——**不要"顺手改成 403"**，那会让攻击者能枚举出哪些帖存在。

**坑 3：`scope` 有四个值，你只负责 `team` 那个。** 枚举已经冻结，别自己加第五个。

**坑 4：团队帖子是不是 `posts` 表的行？** 需要先想清楚。如果是，你得跟 core 打交道；如果是 P2 的 `documents`，你得等 P2。**开工第一件事是跟 P2 确认这个。**

**坑 5：通知要接进现有机制。** 现有的 `notifications` 表是 core 的（你只读不写），但**触发通知的接口在 core 里**。你要么请求 core 加一个通知类型，要么先用现有的类型。别自己建 notification 表。

## 九、常见问题

**Q：我可以改 `src/modules/core/routes-a.js` 里的一个小地方吗？**
A：不行。那是现有论坛的接口，改了 `check-golden.mjs` 会红，而且红在哪很难查。真有需求，先提出来。

**Q：我要的数据在别人的表里怎么办？**
A：用 `ctx.db` 直接读（表结构是公开的），或者看 `ctx.store` 里有没有现成的方法。**不要 import 别人的文件。**

**Q：我新增了文件，为什么测试没报错？**
A：因为哨兵没调。去 `scripts/check-encoding.mjs` 的 `REQUIRED_FILES` 里加上你的新文件，把 `MIN_CHECKED` 加 1；前端新增页面就同步调 `check-ui-contract.mjs` 的 `MIN_UI_CHECKS`。**不做这一步，测试会静默变绿、漏洞静默变大。**

**Q：`check-golden.mjs` 红了怎么办？**
A：说明你改到了现有行为。先 `git stash` 看你到底改了哪些文件，**大概率是你碰了 `src/core/` 或 `src/modules/core/` 里的东西**。绝对不要用 `--write` 重新采样来"修好"它——那是把行为改变合法化。

**Q：`node --test` 报 EPERM？**
A：预期内。这个项目**不用** `node --test`，照抄 `scripts/smoke.mjs` 的写法。

## 三、你的地盘（只动这些）

### 后端

```
src/modules/ui/            ← 你的整个目录，随便建文件
   index.js                            ← 模块声明 + install(ctx) 里建表登记路由
```

**接口前缀：`不新增接口`** —— 只在这个前缀下加路由。

### 表的归属

| 表 | 谁建 | 说明 |
|---|---|---|
| 表 | 归谁 | 说明 |
|---|---|---|
| **你没有表** | — | 这个模块是**纯表现层**。动数据就要回到自己的模块去加接口，不要在这里偷偷建表。 |
| `users` `posts` `boards` `notifications` | core | 只读（`reads` 数组里已经声明） |

建表**不要自己写 `CREATE TABLE` 执行**，要登记：

```js
ctx.schema.add('（无）', `
  CREATE TABLE IF NOT EXISTS （无） (
    ...
  );
`, 'ui');
```

表名必须出现在 `index.js` 的 `owns` 数组里，否则 `check-skeleton.mjs` 会报错。

### 前端

```
public/views/shell.js（如果需要新页面）      ← 新建，你的页面
public/css/改现有 public/css/*（也可以新建自己的分片）         ← 新建，你的样式（两位数字前缀决定加载顺序）
scripts/ui-smoke.mjs           ← 新建，你的端到端测试
```

注册页面要在 `public/app.js` 加一行 import、在 `public/core/router.js` 加一段路由。样式要在 `public/style.css` 顶部加一行 `@import`。

### 合并时你只动一行

`src/modules/index.js` 的 `MODULES` 数组里加一项：

```js
export const MODULES = [core, ui];
```

## 八、你这一路最容易踩的坑

**坑 1：`@import` 必须写在文件最前面。** 这是 CSS 规范，所以 `public/style.css` 里不能出现任何真实规则。你新增分片要在那里加一行 `@import`。

**坑 2：分片文件名前面的两位数字决定覆盖顺序。** 数字小的先加载、数字大的后加载会盖住前面的。想在 `10-base` 和 `20-components` 之间插东西，就叫 `15-xxx.css`。

**坑 3：改类名会让契约检查静默失效。** `check-ui-contract.mjs` 是靠**字符串扫描**找 `class="..."` 的。你要是改用 `className` / `classList` / 组件封装，断言会**静默变绿**（`used` 集合变小 → 恒真）。所以脚本里有 `MIN_UI_CHECKS = 200` 这个下限——**你新增或搬动前端文件后，要把这个数字往上调**，否则漏洞静默变大。

**坑 4：你改了别人要用的界面，要提前说。** 合并顺序里你排在中间（P2 → P1 → **P5** → P3 → P4），因为你一动，别人的页面可能就错位了。

**坑 5：`public/index.html` 只有两个 script 标签。** 页面的装配靠 `public/app.js` 的 import 链，**不要在 index.html 里逐个列出模块**——那些文件没有顶层副作用，列错了就 404（历史上真的发生过：有人往 index.html 塞了 23 条 script 和 10 条 link，全部指向不存在的文件）。

**坑 6：有一个搜索框的坑别踩回去。** ``.search input` 和通用表单样式 `input[type="search"]` 优先级相同（都是 0,1,1），但通用表单样式排在后面，所以它说了算，会把左内边距盖成 12px、放大镜图标正好压在「搜索帖子…」占位文字上。现在靠 `public/css/10-base.css` 里那条 `.search input[type="search"] { padding: 9px 14px 9px 38px; }`（优先级 0,2,1）钉住。**那条别删，注释里也写了原因。**

## 九、常见问题

**Q：我可以改 `src/modules/core/routes-a.js` 里的一个小地方吗？**
A：不行。那是现有论坛的接口，改了 `check-golden.mjs` 会红，而且红在哪很难查。真有需求，先提出来。

**Q：我要的数据在别人的表里怎么办？**
A：用 `ctx.db` 直接读（表结构是公开的），或者看 `ctx.store` 里有没有现成的方法。**不要 import 别人的文件。**

**Q：我新增了文件，为什么测试没报错？**
A：因为哨兵没调。去 `scripts/check-encoding.mjs` 的 `REQUIRED_FILES` 里加上你的新文件，把 `MIN_CHECKED` 加 1；前端新增页面就同步调 `check-ui-contract.mjs` 的 `MIN_UI_CHECKS`。**不做这一步，测试会静默变绿、漏洞静默变大。**

**Q：`check-golden.mjs` 红了怎么办？**
A：说明你改到了现有行为。先 `git stash` 看你到底改了哪些文件，**大概率是你碰了 `src/core/` 或 `src/modules/core/` 里的东西**。绝对不要用 `--write` 重新采样来"修好"它——那是把行为改变合法化。

**Q：`node --test` 报 EPERM？**
A：预期内。这个项目**不用** `node --test`，照抄 `scripts/smoke.mjs` 的写法。

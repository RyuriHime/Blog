# P1 · 动态 —— 开工说明

## 一、你要做的事，一句话

把网站的首页从「板块 + 帖子列表」换成一条**动态时间线**：随手发一句话/一张图/一个链接，能点赞，能设定「谁看得见」，能 @ 人。**没有专用的编辑页面，只有一个纯编辑框**，但仍然支持 LaTeX 和 Markdown。

详细需求（逐条带编号）：`docs/01-需求规格说明书.md` 里 P1 那一段。

**你这一路的规模：** 前端工作量最大（时间线、发布框、图片上传、可见范围选择器），后端相对轻。

**依赖：** 几乎独立。你只是**引用**现有的帖子，不拥有 `posts` 表。

## 三、你的地盘（只动这些）

### 后端

```
src/modules/feed/            ← 你的整个目录，随便建文件
   index.js                            ← 模块声明 + install(ctx) 里建表登记路由
```

**接口前缀：`/api/feed/*`** —— 只在这个前缀下加路由。

### 表的归属

| 表 | 谁建 | 说明 |
|---|---|---|
| `feed_items` | **你** | 动态本身：作者、正文、可见范围、时间 |
| `feed_reactions` | **你** | 动态的点赞（主键 `(user_id, feed_item_id)`） |
| `posts` `users` `follows` `blocks` `notifications` | core | **只读**，可以读，不许写 |

建表**不要自己写 `CREATE TABLE` 执行**，要登记：

```js
ctx.schema.add('feed_items', `
  CREATE TABLE IF NOT EXISTS feed_items (
    ...
  );
`, 'feed');
```

表名必须出现在 `index.js` 的 `owns` 数组里，否则 `check-skeleton.mjs` 会报错。

### 前端

```
public/views/feed2.js      ← 新建，你的页面
public/css/31-feed2.css         ← 新建，你的样式（两位数字前缀决定加载顺序）
scripts/feed-smoke.mjs           ← 新建，你的端到端测试
```

注册页面要在 `public/app.js` 加一行 import、在 `public/core/router.js` 加一段路由。样式要在 `public/style.css` 顶部加一行 `@import`。

### 合并时你只动一行

`src/modules/index.js` 的 `MODULES` 数组里加一项：

```js
export const MODULES = [core, feed];
```

## 八、你这一路最容易踩的坑

**坑 1：不要往 `/api/posts` 上加东西。** 那 13 条路由是 core 的，你要自己的 `/api/feed/*`。

**坑 2：动态和帖子是两种东西，别混。** 需求里写的是「可以发帖链接」——也就是动态里**引用**一个帖子，而不是把动态存成帖子。所以你的表存的是「动态」，`posts` 表你只读不写。

**坑 3：黑名单要生效。** 现有 `posts` 的列表 SQL 里有 `BLOCKED_AUTHOR_SQL`（两处 `?`），你查时间线时也要把黑名单的人的动态过滤掉，不然用户会看到自己屏蔽的人。

**坑 4：这里曾经踩过一个真坑。** `src/store.js` 的 `listPostsByIds` 传参顺序曾经和 SQL 占位符顺序不一致（SQL 是「6 个浏览者状态 → 帖子 id → 黑名单 2 个」，代码传成「6 个浏览者 → 黑名单 → ids」），导致转发列表整个 500。**修完之后 `smoke.mjs` 242 项和 `check-ui-contract.mjs` 175 项全绿——两套测试都覆盖不到这个顺序错误。** 你写多参数 SQL 时，`?` 和参数要成对同序写，别分开写。

**坑 5：图片压缩在前端。** 现有代码有 `compressImageFile(file, maxSize)`，在 `public/core/events.js` 里，直接复用。

## 九、常见问题

**Q：我可以改 `src/modules/core/routes-a.js` 里的一个小地方吗？**
A：不行。那是现有论坛的接口，改了 `check-golden.mjs` 会红，而且红在哪很难查。真有需求，先提出来。

**Q：我要的数据在别人的表里怎么办？**
A：用 `ctx.db` 直接读（表结构是公开的），或者看 `ctx.store` 里有没有现成的方法。**不要 import 别人的文件。**

**Q：我新增了文件，为什么测试没报错？**
A：因为哨兵没调。去 `scripts/check-encoding.mjs` 的 `REQUIRED_FILES` 里加上你的新文件，把 `MIN_CHECKED` 加 1；前端新增页面就同步调 `check-ui-contract.mjs` 的 `MIN_UI_CHECKS`。**不做这一步，测试会静默变绿、漏洞静默变大。**

**Q：`check-golden.mjs` 红了怎么办？**
A：说明你改到了现有行为。先 `git stash` 看你到底改了哪些文件，**大概率是你碰了 `src/core/` 或 `src/modules/core/` 里的东西**。绝对不要用 `--write` 重新采样来"修好"它——那是把行为改变合法化。

**Q：`node --test` 报 EPERM？**
A：预期内。这个项目**不用** `node --test`，照抄 `scripts/smoke.mjs` 的写法。

# 本地怎么试（note-agent 真机验证手册）

这份文档只讲**你自己动手怎么看效果**。代码说明看 [`README.md`](README.md)，接回编辑区的步骤看 [`INTEGRATION.md`](INTEGRATION.md)。

## 一、起服务

在 `D:\Project1\Work\.merge-ai\forum` 目录里打开 PowerShell：

```powershell
.\start-local.ps1
```

然后浏览器打开 **http://127.0.0.1:3456**，用 **alice / demo1234** 登录（管理员视角用 admin / admin123）。

这个脚本做的事只有三件：把端口指到 3456、把模型指向真 deepseek-flash、把数据库指到本副本的 `data\forum.db`。
**不会碰线上那套**（`/opt/dsh-forum` 与 systemd 的 `dsh-forum` 服务各跑各的）。停止服务按 `Ctrl+C`。

几个开关：

| 想要什么 | 怎么做 |
| --- | --- |
| 换端口 | `.\start-local.ps1 -Port 4000` |
| 关掉刷屏的请求日志 | `.\start-local.ps1 -Quiet` |
| 换 API key | 改脚本里的 `AI_API_KEY` 那一行（只影响这个本地服务） |

> 时间预期：**整理**和**提需求**各 30~60 秒，**学术审查** 15~45 秒。deepseek-flash 的思维链也要花 token，慢是正常的，不是卡死。

## 二、手点一遍（约 5 分钟，这是最值得做的验证）

先看清楚两件事：**面板不是上传入口，它盯着「正文」那块输入框**（所以整个流程里你不需要准备任何文件）；
**面板是左边一个 420px 的抽屉**（右边留给宿主自己的侧栏），右边照样能看编辑区、左边改，顶上「›」收起来、左边竖标签「✨ AI 笔记整理」再打开。

### 第 1 步：面板知道自己现在在看什么

1. 点右上角「发帖」，进入 `#/new` 写作页。
2. 看左边抽屉「✨ AI 笔记整理」。**此时编辑区是空的**，按钮应该是点不动的（灰的），提示你「编辑区还是空的」。
3. 顺手点一下抽屉右上角的「›」再点左边的竖标签：**收起、展开都要顺畅**，收起后右边的编辑区要能完整看到。

**要看的是**：抽屉默认在左侧展开、收起后只留一条竖标签（点它回来）；**窄屏（≤1080px）默认是收起的**，展开时是覆盖式而不是把编辑区挤没。按钮的可用状态必须跟着编辑区内容走。

### 第 2 步：一边打字，一边看面板跟上（这一步不花钱）

在正文里贴一段**结构乱、但内容真实**的草稿。建议直接复制这段（就是真机验收用的那段）：

```markdown
导数是变化率，这是微积分里最基础的一句话。

$$f'(x_0) = \lim_{h \to 0} \frac{f(x_0 + h) - f(x_0)}{h}$$

## 二、积分

积分是累积量。
```

**要看的是**：

- 顶部状态胶囊里出现 ✅ **正在跟随编辑区 · N 字**，字数跟着你打字实时变；
- 下面出现大纲行「导数与积分 ／ 一、导数的定义 ／ 二、积分」；
- **「效果预览」区里已经能看到渲染好的样子**（标题是大字、公式是原样的 `$$…$$`——论坛没有数学排版，这是正常的）；
- 点预览右上角的「原文 / 效果」可以来回切：**原文**显示 Markdown 源码，**效果**显示渲染结果，右边那个 ⟳ 是手动刷新。

**这一整步一次模型都不调**（浏览器 F12 → Network 里只有 `/api/notes/session` 和 `/api/markdown/preview`）。这是设计上的承诺：**不点按钮，不花一分钱**。

### 第 3 步：点「整理这篇笔记」

点下去之后等 30~60 秒。**要看的是**：

- 「整理结果对比」里逐块列出**改了什么**（左删右加），而不是把整篇重写一遍；
- 如果模型觉得某处**信息不够、不能凭空补写**，它会在对比栏上方用一句话问你（比如「二、积分是否补充定积分定义？材料里没有，无法凭空补写」）——这是它在守规矩，不是报错；
- 如果你这次只打了十几二十个字，会出现「这次没有需要改动的地方，草稿保持原样」——也是正常结果；
- **画面上方始终留着「效果预览」**：跑完一轮之后对话、提示、对比、审查卡都长出来了，面板会自动滚回顶部，预览还在你眼前；就算你自己往下翻看意见，预览也钉在抽屉顶部不跑掉；
- **「对话记录」里多出一条**，右端写着这一版的字数和一个「回滚到这一版」的小按钮。

### 第 4 步：点「应用到编辑区」

**要看的是**：

- 编辑区里的字真的变了，标题栏也填上了（比如「导数与积分：从变化率到累积量」）；
- **公式不能出现两层 `$$`**，**表格不能出现两行 `| --- |`**（这两个是早前修掉的真 bug，值得顺手复验）；
- 胶囊变成两颗：左边「正在跟随编辑区 · N 字」，右边「草稿 · 7 块 · M 字 · 3 级标题」。**两颗字数不一样是对的**——左边是编辑区此刻，右边是工作台草稿。

### 第 5 步：在输入框里提一条要求，点「提需求」

比如输入「把第一段补一句导数几何意义的引入，说明导数刻画变化快慢」。

**这一步是重点，要看三件事**：

1. **编辑区一个字都没动**（你没点应用，它就不许改你的正文）——可以先记住编辑区字数，点完再对一遍；
2. 对比栏里**只有该动的块**被标出来，其它块不动；
3. 左边那颗胶囊会补一句「（草稿 M 字）」——意思是**草稿已经和编辑区不一样了**，等你确认。

### 第 6 步：点「学术审查」

等 15~45 秒。**要看的是**：

- 「找到 N 条意见」，每条都带**原文引用**、严重度标签（high / medium / low）和类型（structure / fact / formula / clarity…）；
- 内容应该是**学术性**的（定义是否严谨、有没有区分定积分与不定积分、公式前提有没有交代），而不是「语句通顺」这种场面话；
- 底部有「一键应用高优先级修改」，只会动 high 那几条。

### 第 7 步：回滚到之前某一版（聊天框最该有的那个能力）

在「对话记录」里挑**最早那一条**（就是刚整理完的那一版），点它右边的「回滚到这一版」。

**要看的是**：

- **编辑区还是一个一个字都没动**——回滚只换面板手里的草稿与预览，写回编辑区仍然要你点「应用到编辑区」；
- 上面那颗胶囊不再报「（草稿 M 字）」，预览也换成了那一版的内容；
- 被你回滚掉的旧轮**没有消失**，只是灰掉了，旁边标着「已回滚」；标题栏左边出现「回到最新」，点它能回到最新那一版；
- 历史只增不减——回滚这个动作本身也留了一条记录。

### 第 8 步：刷新、离开再回来

- 刷新页面，面板应该恢复成「已存在的会话」状态，不重复建，**对话记录里的历史也还在**；
- 从写作页走到别处再回来，`#notesMount` 里**只应有一个面板**（不能叠两个）。

## 三、想知道每一步到底对不对，可以让机器替你验

打开第二个 PowerShell 窗口（服务要继续开着）：

```powershell
cd D:\Project1\Work\.merge-ai\forum
node scripts/run-tests.mjs
```

基线是 **6 / 6 套全绿**（站点冒烟 242 项 / UI 契约 175 项 / 知识网络图 28 项 / forum-ai 61 项 / note-agent / notes 端到端 50 项）。这套跑的是**假模型**，不花钱、几秒出结果；它验的是契约、边界和「不点就不改编辑区」这类承诺。

只跑 note-agent 自己的测试：

```powershell
node note-agent/scripts/run-tests.mjs
```

## 四、它也能脱离论坛单独跑（证明不是长在宿主里的）

```powershell
cd D:\Project1\Work\.merge-ai\forum
node note-agent/examples/server.mjs
# 打开 http://127.0.0.1:3480
```

这个例子是 `node:http` + `node:sqlite` 写的最小服务，**没有一行论坛代码**，自带一个假编辑器页面。它证明这个包可以整包搬走；也正因为有这个契约，将来论坛换成非 textarea 的编辑器时，面板不用改（见 `note-agent/EDITOR-CONTRACT.md`）。

## 五、试出来问题怎么反馈给我

最有用的三样东西：

1. **你点了哪个按钮**、之前编辑区里大概是什么内容；
2. **界面上的原话**（错误提示、状态胶囊、对比栏文案），或者直接截个图；
3. 如果服务窗口里有红色报错，把那几行贴给我（里面有 `ai_bad_json` / `ai_timeout` / `notes_not_configured` 这类错误码，能直接定位到是哪一层出的问题）。

> 临时脚本 `start-local.ps1`、本文档与残留的 `_srv*.log` 都是**验收用辅助件**，你确认可用之后我会决定是删掉还是整理成正式入口。
